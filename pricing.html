Pretense sits between developers and the AI tools they use, like a proxy on the machine. Before any code or prompt reaches an LLM, it always swaps secrets, SSNs and card numbers for realistic stand-ins and swaps email addresses and phone numbers under every framework profile except PCI and anywhere they are labeled. The AI works on the safe version. When the response comes back, the code names are restored. Secrets and PII stay as stand-ins and are never put back into the reply. Real secrets and code names stay on the machine.

Sensitive values that Pretense mutates stay on the local machine. Secrets such as credentials and API keys, SSNs and card numbers are always swapped for stand-ins before anything is sent, so the model sees a stand-in for each detected value. Email addresses and phone numbers are swapped under every framework profile except PCI and anywhere they are labeled. Without a profile, or under PCI, unlabeled email addresses and phone numbers leave the machine as written. Function, class and variable names are renamed too. Code names are restored locally when the response returns. Secrets and PII stay as stand-ins and are never put back into the reply. If a model copies a stand-in into a link, the link carries the stand-in in place of the real value.

Traditional DLP guards a different channel. It was designed for email and file uploads. Pretense is designed for the prompt. When DLP flags a prompt, it blocks or redacts the content, which strips the context the AI needs to answer. Pretense swaps sensitive values for stand-ins, so the data stays protected and every answer keeps its full quality.

Accuracy holds at full strength. That is the design. Redaction tools delete the sensitive parts, which strips the context the model relies on across a session. Pretense swaps values for stand-ins that keep the same structure, so the model keeps the context it needs to give a useful answer.

Pretense detects the sensitive parts before they reach the AI. Secrets, SSNs and card numbers are always mutated. Email addresses and phone numbers are mutated under every framework profile except PCI (SOC 2, HIPAA, GDPR, ISO 27001, CMMC L2, NIST) and anywhere they are labeled. Start the proxy with pretense start --framework <profile> to choose the profile. Each match becomes a realistic stand-in that keeps the same structure, so the code still works and the AI can still reason about it. Function, class and variable names are renamed as well. Once the response comes back, the code names are restored on the local machine. Secrets and PII stay as stand-ins and are never put back into the reply.

On the local machine. Pretense runs locally as a proxy, so the sensitive values are swapped before anything is sent. Real data stays off Pretense servers.
