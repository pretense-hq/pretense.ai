US Export Controls Lead Anthropic to Suspend Claude Fable 5 and Mythos 5 Worldwide

On June 12, 2026, the US Department of Commerce ordered Anthropic to cut off access to its two newest models, Claude Fable 5 and Claude Mythos 5, for any foreign national anywhere in the world.

Anthropic lacked a reliable way to check a user's nationality in real time, so it disabled both models for every customer on earth. The blackout ran 19 days. Customer data stayed exactly where it was the entire time, fully intact. But for the engineering teams that had already built Fable 5 into a working process, the model was simply gone, and keeping it running sat entirely outside their reach.

This is a story about a different kind of exposure than a breach: the moment a team discovers that the model underneath its workflow answers to a regulator first and a customer second.

What Happened?

  • -June 9, 2026. Anthropic releases Claude Fable 5 broadly. Mythos 5, the more capable sibling model behind it, had already been in limited release for months through Project Glasswing, a controlled program that gave roughly 40 vetted organizations, including Google, Microsoft, and JPMorgan Chase, early access to harden their own systems.
  • -June 12, 5:21 p.m. ET. The Commerce Department sends Anthropic an export control directive under the Export Control Reform Act, ordering the company to suspend Fable 5 and Mythos 5 for any foreign national, whether located inside or outside the United States, including Anthropic's own foreign national staff.
  • -June 12, that evening. Anthropic posts a public statement. The order takes effect immediately, and verifying a user's nationality at the point of a request is beyond what the company's systems can do, so it disables both models for every customer, everywhere. Opus, Sonnet, and Haiku keep running as usual.
  • -June 26. Commerce Secretary Howard Lutnick tells Anthropic that engagement with the government has made enough progress to allow Mythos 5 back out to a vetted group of cyber defense and infrastructure organizations. Fable 5 stays blocked.
  • -June 30. Commerce lifts the export controls on both models entirely. Anthropic publishes a post titled "Redeploying Claude Fable 5."
  • -July 1. Fable 5 returns to every user, globally, across Claude.ai, the Claude Platform, Claude Code, and Claude Cowork.

A jailbreak report, separate from any data leak

The trigger traces back to Amazon, a major Anthropic investor. Amazon researchers found a way to prompt Fable 5 around its safety guardrails, a technique known as a jailbreak, and got the model to identify a software vulnerability. In one case, the researchers say, the same technique produced code demonstrating how the vulnerability could be exploited. Amazon disclosed the finding directly to the US government ahead of Anthropic.

Given how loudly Anthropic had marketed Mythos-class models around advanced, autonomous cybersecurity ability, calling Mythos 5 capable enough to warrant its own government-linked early access program, regulators treated the report as a live national security concern well beyond a routine bug.

Anthropic pushed back hard on the severity of it. Its own testing found that Opus 4.8, OpenAI's GPT-5.5, and Moonshot's Kimi K2.7 could all be prompted to find the same class of vulnerability using similar techniques, meaning other models shared the same underlying capability. Anthropic CEO Dario Amodei was publicly blunt that he saw the jailbreak as minor, far short of what would justify the directive. The government's letter, for its part, gave Anthropic little to work from beyond a verbal account of the incident it was responding to.

Both things can be true at once. The underlying capability likely existed across several labs' models already. The government still had the authority to treat Fable 5 as the one that mattered, and it did.

Export controls used to be something you could plan around

Traditional export control works on a principle Hamilton Mann, executive chairman of the Artificial Integrity Institute, calls ex ante restriction. A chip maker knows in advance which countries a part is barred from. A defense contractor knows which technical data must stay on which side of which border. Teams build around a known boundary.

The Fable 5 order was something else: an ex post withdrawal. Anthropic had already shipped the product. Enterprises had already integrated it, trained staff on it, wired agents around it. Then the boundary moved backward in time and reached into systems that were already live. Mann's framing is useful here because it names the actual shift: this is closer to a supplier halting deliveries mid-contract, or a cloud region disappearing overnight, than to a familiar compliance boundary a legal team already had on its checklist.

What actually stays in a team's control

Keeping Fable 5 running on June 12 sat outside every engineering team's reach. That decision sat entirely with Washington and Anthropic. What a team controls is what leaves its own machines before any of it reaches a model, regardless of which model that happens to be on a given day.

That is the part of this story relevant to Pretense, the AI data security tool this case study lives on.

Pretense is a local proxy that swaps secrets, API keys, tokens, and code identifiers for deterministic stand-ins before a prompt reaches an AI tool. Identifiers are swapped back byte-exact in the answer; secrets stay as stand-ins by design. It is model-agnostic across Claude, GPT, Gemini, and others. Because the protection is tied to the machine, data safety is settled before any vendor switch, even under pressure. It is one option among alternatives, and government directives sit outside its scope.

Four things to check this week

  1. -List every workflow with a single point of failure. If one specific model disappeared tomorrow, which processes go down, and who finds out first: the team, or a customer?
  2. -Actually test the fallback, beyond just naming it. A model that has only ever touched test traffic before showing up in a disaster recovery document is a guess dressed up as a plan.
  3. -Confirm the data protection layer works independently of any single vendor's API. If switching models means rebuilding the security review from scratch, the fallback plan has a second single point of failure hiding inside it.
  4. -Add sudden model unavailability to the same runbook that already covers cloud and vendor outages. This has become a recognized category of operational risk in its own right, alongside the outages already on that list.

How I run Pretense on my own code

I build Pretense with Claude Code, and my sessions run through it. Here is the setup I give a new engineer, in order.

  1. -Run the agent through the proxy. Type pretense run claude where you would type claude. It starts a local proxy on port 9339, points Claude Code at it and stops the proxy when the session ends. Detected secrets and PII leave the laptop as stand-in tokens.
  2. -Put hooks on every repo. pretense install adds a pre-commit and a pre-push hook. A key that never lands in git is a key an agent never reads.
  3. -Scan before an agent reads the repo. pretense scan path . lists what it finds. In CI, pretense scan ci exits 0 when clean, 2 on findings and 3 when it examined nothing. Treat 3 as a failure.
  4. -Preview the swap. pretense review . shows what would be mutated. pretense mutate <file> --preview prints one file mutated and leaves the file on disk as it was.
  5. -Round-trip a file you need to share. pretense mutate <file> --map <map> swaps the secrets in place. pretense reverse <file> --map <map> turns it back into the original, byte for byte, from the encrypted map on your machine. We run that round trip on real files before every CLI release and compare sha256 hashes.

One thing I learned the hard way: inside a session the agent sees stand-ins, so a file the agent writes can hold a stand-in where you expected a real value. Grep what the agent wrote before you ship it.

What Pretense will not do is put a secret back into the model's answer. Code identifiers come back byte-exact. Secrets and PII stay as stand-ins in the response. That is deliberate: a prompt-injected model can echo a token into a link, and reversing it there would hand over the real key.

What this means if you lead an engineering team

The outcome: your team keeps asking AI assistants about real systems, configs and connection strings, and detected secrets leave each laptop as stand-ins.

  • -No new workflow. Engineers type pretense run claude in place of claude. Other AI CLIs run the same way, for example pretense run gemini.
  • -Guard the repo as well as the prompt. pretense install adds pre-commit and pre-push hooks. pretense scan ci in the pipeline fails on findings (exit 2) and on an empty scan (exit 3).
  • -Answers stay usable. Identifiers inside fenced code blocks go out as stand-ins and come back byte-exact, so the code the model writes still uses your names.
  • -Measure before you mandate. Run it on your own repo for a week. pretense audit shows what it swapped and when.
